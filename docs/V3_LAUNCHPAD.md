# v3 destination-branch publishing

The latest user requirement supersedes ZIP-first navigation: select repository → select existing branch from GitHub → choose ZIP → select content mode → review → commit directly to that branch. The indigo/teal Launchpad remains, but normal uploads have no free-text branch fields, separate base/new-branch choice or compulsory extra branch. The branch sheet loads every page, allows searching loaded results while loading continues, labels the default/protected branches, and requires an explicit selection. New repositories still use the existing creation recovery runner and initialized default branch. Empty repositories can be explicitly initialized from the branch sheet without overwriting README.md.

Changes only is the default: add/update included paths, preserve absent files, reuse unchanged objects. Full project is explicit root replacement: absent included-ZIP paths become reviewed deletions. It does not alter other branches, repository settings or commit history. Exclusions are disclosed, with a warning that excluded files can correspond to deletions. Folder removal is opt-in to preserve src/... paths in partial ZIPs. An optional destination folder remains available only for Changes only. A no-op preview shows Already up to date and does not create a commit/history attempt.

The selected branch supplies the preview base and receives the final commit. Batched text/deduplicated binary staging and full tree/hash verification remain. Direct publication uses GraphQL updateRefs with an exact nonzero beforeOid, the generated afterOid and force:false. A concurrent branch advance OR rewind therefore prevents publication. No automatic fallback to a force push, a new branch or an unguarded REST update is allowed. Branch protection and permissions remain enforced by GitHub. Staging objects have bounded retries; the branch-update mutation is never automatically repeated.

Checkpoints record the publication kind and possible final-write start. Unknown results remain blocked until checked. The read-only inspector verifies repository identity and whether the recorded commit is now at the branch tip or in its history; absence is described as current absence, not proof the request never ran. Checking updates local metadata only and never republishes. Fresh review is required before a new attempt. Legacy new-branch publication remains an internal compatibility path, not the active UI.

Authentication, app registration, CI, upload limits, pacing and foreground-only execution are unchanged. ZIP bytes remain account-scoped RAM only. No build, tests, lint, typecheck, CI inspection, live GitHub mutation test or post-push verification is performed. Included protocol tests are source only; API/device behavior remains unverified.
