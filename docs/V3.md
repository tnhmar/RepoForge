# v3 — ZIP publication only

v3 was created directly from v2 at d4f3b179d07a39d7f5980831d130da1d31bc1852. Do not copy or merge main into it. The v3 product scope supersedes the broader seven-commit collaboration redesign for this branch.

## Change 1: upload engine and CI

Text files use actual multi-file Git tree requests, not one blob POST per file. Each application batch is capped at 100 tree entries and 1 MiB of serialized UTF-8 JSON including envelope/path/escaping overhead. These are conservative APP limits, not a claim about GitHub's maximum POST size. Only lossless UTF-8 files of at most 256 KiB qualify for inline content. Empty text is supported. Invalid UTF-8, NUL-containing or larger files use deduplicated base64 blob requests with the existing 8-second write pacing. Known base/checkpoint blobs are reused. Binary files are not claimed to have a nonexistent REST bulk-blob endpoint.

Intermediate trees are unreferenced. The full final tree is checked against the reviewed paths, modes, types and SHA-1 hashes; truncation is rejected. Only one project commit and a new destination branch are published, without force updates. Replacement/deletion review, base-head checks and cancellation remain. Unknown final ref creation is not retried automatically. A checkpoint marks when publication may have started. Object writes alone have bounded retries; Retry-After/reset headers and secondary-rate cooldowns are respected. Authentication remains centralized and queued requests reject account changes.

CI push branches are main, v2 and v3. The Android build credential guard includes v3 but still excludes pull requests. APK artifacts are built by the existing pipeline; the shared latest-apk release remains main-only, so v3 does not overwrite it. No secret values, callback registration, dependencies or production signing are changed.

The inherited ZIP parser still enforces 20 MiB compressed, 50 MiB extracted, 300 regular files, 1,000 directory entries and 5 MiB per file. Some inherited UI/error copy incorrectly advertises higher values; correct that copy in the focused UI change, not by silently raising memory limits. The 7 MB GitHub recursive GET-tree response limit is NOT a tree-upload batch allowance.

## Change 2: focused app — remaining

After sign-in, select an installed repository or create an initialized personal/organization repository, then choose/configure/review/publish a ZIP. Read the selected repository's actual default branch. Preserve explicit initialization for empty repositories, creation unknown-result recovery and upload history. Replace the broad shell and redirect legacy code/issue/PR/Actions/release entry routes so those tools are not part of the active v3 app. Keep account/access controls only as support for publishing.

This first change does NOT yet remove the broad v2 screens. Existing old screens continue to call the new publication engine through the unchanged publish API. Numeric progress has a callback seam for the focused upload UI.

## Verification / execution boundaries

Source and tests are prepared, not verified. No install, lint, typecheck, test, build, CI inspection or post-push check is run in this workflow. No durable native background worker is added: uploads still require a live foreground process and project bytes are not automatically restored after process death. Check GitHub before retrying an unconfirmed publication.
