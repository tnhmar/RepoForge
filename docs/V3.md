# v3 — focused ZIP publisher

One combined change on v3, based directly on v2 at d4f3b179d07a39d7f5980831d130da1d31bc1852. The earlier partial engine-only proposal is superseded. Main and v2 are not targets.

Active flow: GitHub sign-in → select connected repository or create initialized repository → choose ZIP → configure → review → publish → result/history. Account/access/preferences are support utilities. No active collaboration, Actions, releases, notifications inbox or code-browser UI. Legacy work/workbench routes redirect to repository selection; repository routes redirect to ZIP import. Live.tsx is compatibility exports, not a second UI. Unrouted ancestral feature modules remain in Git history/source; they are not exposed by the active route graph.

Creation uses the existing checkpoint runner, including explicit unknown-result lookup/adoption and unfinished-setup recovery. New repositories have a README. Existing empty repositories require separately confirmed initialization without overwriting a file. The uploader reads the real default branch rather than assuming main. Review lists are virtualized; deletion acknowledgement and final publication confirmation remain. Foreground progress includes batch/stage and prepared-file counts. Prepared contents do not mean publication success.

Upload optimization: lossless UTF-8 content up to 256 KiB per file is inlined into multi-file Git tree requests. Batches are bounded to 100 entries and 1 MiB of actual serialized UTF-8 JSON, including envelope/escaping/path overhead. These are APP safety limits, not GitHub hard maxima. Binary/large files use deduplicated base64 blobs with paced requests. Known Git objects are reused. Delta trees use the reviewed base tree, so unchanged repository entries are not resent; blocking deletions precede additions. HTTP 413 can split batches. Intermediate objects do not update a branch. Final complete-tree paths/types/modes/hashes are checked before a single commit and new ref; no force-push. Final ref requests are never automatically repeated after ambiguous outcomes. Server Retry-After/reset headers and secondary-rate cooldowns are honored; account changes stop queued requests. Checkpoints contain metadata, not ZIP bytes, and are not a durable native worker.

ZIP parser safeguards are unchanged: 20 MiB compressed, 50 MiB extracted, 300 regular files, 1,000 directory entries, 5 MiB per file, plus CRC/path/collision/expansion checks. The active UI translates two misleading inherited parser error strings to the actual enforced limits. No memory limits are silently raised.

CI includes v3/main/v2 push events and v3 in the Android build-credential guard, with PR secrets excluded. APK artifacts remain supported; the shared latest-apk release stays main-only. Registration values, auth/PKCE/token rotation, dependencies and production signing are unchanged.

No build/test/lint/typecheck/CI inspection or post-push verification is performed. Included tests are source only, not reported passing. GitHub runtime behavior and Android operation remain unverified. Uploads require a live foreground process: no automatic project-byte restoration after process death and no durable background execution claim. This v3 scope replaces the broader collaboration-redesign plan for this branch.
